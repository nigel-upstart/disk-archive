# Synthetic redaction oracle and reference retirement

**Owner:** Maintainers · **Status:** Provenance retained; reference retirement pending integration
**Last updated:** 2026-10-24 · **Links:** [reference](../legacy/python/README.md), [Rust comparison](../crates/core/tests/golden.rs), [original reference PR](https://github.com/nigel-upstart/disk-archive/pull/11)

The 16 frozen redactor cases are invented input bytes and findings, not credentials or sampled
session logs. Expectations were generated by the sanitized repository Python redactor, not by
Rust. They pin output bytes and replacement counts; Rust's `golden_parity` test compares both from
the lasting [`fixtures/redactor`](../fixtures/redactor/) copies. The sanitized original remains
in place until the relocated Rust comparison freshly passes; no removal is finalized here.
They do not establish scanner recall, encoded-secret coverage, full pipeline parity, upload
integrity, deletion safety or performance equivalence.

Cases cover literal/raw-v2 and JSON-escaped replacement, longest-first overlaps, multiline
pieces and their 12-character cutoff, env assignments, inline/multiline/unterminated PEM,
line drops, empty input, non-UTF8 and missing-final-newline behavior. Rust adds independent
fail-closed guards and bounded-resource tests; frozen parity is deliberately narrower.

During preparation, `task parity` checks the frozen SHA-256/schema/count/ordered-ID integrity,
then runs the original sanitized Python oracle and the real Rust byte/count comparison. The
integrity checker ([source](../scripts/frozen-oracle.py)) does not execute either redactor or
establish parity by itself. The gate retains both real executions and fails if either fails. Python validates the actual timestamp-restoration call at legacy
float-second precision and filesystem mtime before reading output. It does not promise a later
atime observation free from external readers. Rust core performs no filesystem rewrite, so its
fixture comparison alone cannot establish timestamp preservation by the application adapter.

## Retirement contract

Only the **sanitized repository** `legacy/python` tree may be retired. Never inspect, move,
delete, execute or modify the production Python installation or artifacts to accomplish this.
Before deletion, rerun the live synthetic oracle and the Rust comparison against all 16 cases,
record the actual receipts, and preserve fixture bytes and this provenance. Preparation has
rerun the Python side only; that is not a new Rust or full-check validation receipt.

Both JSON files are now copied byte-for-byte to `fixtures/redactor/`, and Rust's `include_str!`
paths point there. The original JSON/source tree and its live gate remain intact. Python 3.14.7
freshly checked all 16 original goldens, including timestamp restoration, during this preparation;
the copied hashes/integrity and static references are checked separately. Rust compilation is
blocked by coordinated build ownership/disk capacity, so the relocated Rust comparison has
**not** freshly run. Do not infer it passed from older main/PR parity receipts.

Once the actual Rust comparison passes, remove only the live-reference invocation from
`scripts/golden-parity.sh`, leaving frozen integrity plus the **real Rust comparison**, never an
empty success or self-generated Rust expectation. Keep `task parity` meaningful and label it
frozen-oracle regression, not live Python/Rust execution parity after Python has been removed.
Regeneration from Rust is not allowed. Any deliberate oracle change needs independent evidence
and review against the recorded reference revision.

At retirement, update the README, core test documentation, this document's reference links,
legacy-specific Gitleaks allowances and regression tests together. Gitleaks decodes the hex
fixture input before scanning: the two exact synthetic decoded-match allowances remain necessary.
They now include only the old and lasting exact cases-file paths. Negative controls require
both copies to scan clean but reject changed decoded content, appended synthetic PEM findings
and identical content at an unrelated path. Hash controls independently reject any byte change.
The two legacy-test allowances also remain necessary while their files exist; remove them
alongside those files and replace the old test with a regression that the retired path is no
longer allowed. No directory/rule-wide exclusion or unsafe-Rust permission is introduced. Shared gate/task changes require ownership coordination
with active application/scanner work. The optional TruffleHog scanner comparison is independent
and must not be removed as a side effect of retiring the redactor reference.
